01 · 先学会“读”命令

看到陌生命令，先拆成三段。命令决定做什么，选项改变做法，参数说明对谁做。

student@bbs-lab:~/BBS$ docker logs --tail 50 bbs-mysql
命令docker logs
读取容器输出。
选项--tail 50
只显示最后 50 行。
参数bbs-mysql
目标容器名称。

风险标签

只读检查 改变状态 删除资源 需要 root

提示符：$ 通常表示普通用户，# 通常表示 root。教程里的命令不要把提示符一起复制。

02 · 帮助、历史与系统身份

不确定时先查帮助和当前环境。这些命令主要是只读检查。

命令用途与 BBS 示例观察什么
man docker只读检查打开本机手册。按 q 退出，/word 搜索。本机实际安装版本支持的选项。
docker run --help只读检查查看某个子命令的简要帮助。-p、-v、--name 的格式。
history | tail -20只读检查查看最近执行过的 20 条命令。是否重复执行了启动或删除命令。
clear清理当前终端显示，不删除历史。仅改变屏幕，不改变系统。
whoami / id只读检查确认当前用户、UID 和所属组。是否属于 docker 组。
hostnamectl只读检查查看主机名、系统和内核摘要。虚拟机名称与 CentOS 版本。
cat /etc/os-release只读检查准确识别 Linux 发行版。NAME 与 VERSION_ID。
uname -r / date只读检查查看内核版本和系统时间。排查 Docker 内核兼容性、日志时间偏差。

03 · 文件与目录

命令用途与示例注意
pwd / ls -lah只读检查显示当前位置和包含隐藏项的文件列表。修改文件前先用 pwd 确认目录。
cd /opt/bbs改变状态切换到 BBS 部署目录；cd .. 返回上一级，cd - 返回上一次目录。只改变当前终端位置。
mkdir -p /opt/bbs/logs改变状态 需要 root创建目录及缺失的父目录。/opt 通常需要 sudo。
touch /tmp/bbs-notes.txt改变状态创建空文件或更新时间。不会自动写入内容。
cp application.yml /tmp/application.yml.bak改变状态修改配置前创建明确的备份。复制目录使用 cp -r，先确认目标。
mv /tmp/bbs-notes.txt /tmp/bbs-command-notes.txt改变状态移动或重命名一个明确文件。目标同名时可能覆盖。
rm /tmp/bbs-command-notes.txt删除资源删除一个明确的练习文件。终端删除通常不进回收站；运行前再次核对完整路径。
find /opt/bbs -name "*.log"只读检查在 BBS 目录下寻找日志文件。搜索范围越小越快。

04 · 查看、跟踪与搜索文本

命令用途与示例什么时候用
cat /etc/os-release一次输出较短文件。配置很短时。
less application.yml分页查看长文件；q 退出。查看配置但不修改。
head -20 app.log显示开头 20 行。确认日志头或文件格式。
tail -f app.log持续跟踪新增日志；Ctrl+C 停止跟踪。启动 BBS 时实时观察。
grep -n "ERROR" app.log搜索错误并显示行号。从大日志快速定位异常。
grep -R "spring.datasource" /opt/bbs递归搜索配置关键字。只对明确的小目录使用，避免扫遍整个系统。

以上都是 只读检查。查看日志优先使用 less、tail 和 grep，不要为了查看而改文件。

05 · 用户与权限

-rwxr-x--- 可拆成：文件类型、所有者权限、组权限、其他人权限。数字写法中 r=4、w=2、x=1，所以 750 表示所有者 7、组 5、其他人 0。

命令用途风险
ls -l /opt/bbs只读检查查看所有者、组和权限。先检查再修改。
sudo chmod 750 /opt/bbs改变状态 需要 root允许所有者读写执行、组读执行，禁止其他人访问。不要用 777 作为万能修复。
sudo chown -R student:student /opt/bbs改变状态 需要 root把明确目录交给学习用户。-R 会递归改变全部子项，只能对已核对路径使用。
sudo systemctl status docker只读检查 需要 root临时以管理员权限检查 Docker 服务。sudo 不是每条命令都要加。

Docker 组权限很高：能直接使用 Docker 的用户通常可以获得接近 root 的主机控制能力，只给可信账号使用。

06 · 进程、服务与资源

命令BBS 场景观察或操作
ps aux | grep java只读检查寻找 Spring Boot Java 进程。PID、CPU、内存和启动命令。
top只读检查实时查看资源占用，按 q 退出。CPU 或内存是否持续过高。
kill -15 12345改变状态请求 PID 12345 优雅退出。先用 ps 核对 PID；不要一开始就用强制信号。
systemctl status docker --no-pager只读检查查看 Docker 服务状态。active (running) 和最近错误。
sudo systemctl restart docker改变状态 需要 root确有必要时重启 Docker 服务。会影响该主机上的所有容器，先确认影响范围。
journalctl -u docker -n 100 --no-pager只读检查查看 Docker 服务最后 100 行日志。启动失败、存储或 socket 报错。
free -h / df -h只读检查查看内存和磁盘余量。MySQL/ES 启动前确认资源。
du -sh /var/lib/docker / lsblk只读检查 需要 root估算 Docker 数据目录并查看磁盘结构。只读检查，不直接删除数据目录。

07 · 网络、防火墙与 SELinux

命令用途关键判断
ip addr只读检查查看网卡和虚拟机 IP。忽略 lo，寻找局域网网卡地址。
ss -lntp只读检查查看 TCP 监听端口及进程。排查 8080、3306、6379 是否冲突。
curl -I http://127.0.0.1:8080只读检查从虚拟机内部测试 BBS HTTP 响应头。先本机通，再排查防火墙和虚拟机网络。
ping -c 4 8.8.8.8只读检查做基础网络连通性测试。部分网络会禁 ICMP，失败不等于 HTTP 一定失败。
firewall-cmd --list-all只读检查 需要 root查看当前区域和开放端口。先确认端口是否真的需要从宿主机外访问。
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload改变状态 需要 root		需要从 Windows 访问 BBS 时开放 8080。不要把 MySQL/Redis 无条件暴露到局域网。
getenforce / ls -Z /opt/bbs只读检查查看 SELinux 模式和文件安全标签。遇到权限错误先检查标签，不默认关闭 SELinux。

不要开放 0.0.0.0:2375。未认证 Docker API 等同于把虚拟机控制权交给网络中的访问者。

08 · 软件包与压缩

命令用途CentOS 7 注意事项
yum repolist只读检查列出启用的软件仓库。CentOS 7 停止维护后仓库可能失效；先保留完整报错。
yum info git只读检查查看可用包版本，不安装。先确认来源与版本。
sudo yum install -y git改变状态 需要 root从已配置仓库安装 Git。失败时不要立即替换仓库文件，先记录错误。
rpm -qa | grep docker只读检查查找已安装的 Docker 相关 RPM。与 docker version 结合判断。
tar -czf /tmp/bbs-config.tgz /opt/bbs/config改变状态把明确配置目录打成 gzip 压缩包。输出文件使用明确路径，注意不要把密钥提交到 Git。
tar -tzf /tmp/bbs-config.tgz只读检查不解压，先列出压缩包内容。解压陌生包前先检查路径。

09 · Docker 的四个核心对象

镜像 Image只读模板，例如 mysql:8.4。像安装包，不是正在运行的程序。
容器 Container镜像的一次运行实例，例如 bbs-mysql。可启动、停止、删除。
数据卷 Volume独立保存数据，例如 bbs-mysql-data。替换容器时数据仍可保留。
网络 Network让容器按名称互相访问，例如 bbs-network。
mysql:8.4 镜像  --创建-->  bbs-mysql 容器
                               |--挂载--> bbs-mysql-data 数据卷
                               |--加入--> bbs-network 网络

10 · Docker 环境与镜像

命令用途观察或风险
docker version只读检查分别查看客户端和服务端版本。只有 Client 没有 Server 时，Docker Engine 不可用。
docker info只读检查查看存储驱动、容器数量、镜像数量和资源。输出较长，重点看错误和 Server 段。
docker system df只读检查统计镜像、容器、卷占用。磁盘不足时先看这里，不直接删目录。
docker pull mysql:8.4改变状态下载固定标签的 MySQL 镜像。占用磁盘与网络；标签决定版本。
docker images只读检查列出本机镜像。核对仓库、标签、镜像 ID 和大小。
docker image inspect mysql:8.4只读检查查看镜像详细元数据。入口命令、架构和标签。
docker rmi mysql:8.4删除资源删除明确镜像标签。依赖该镜像的容器存在时通常会拒绝删除。

11 · 容器生命周期

docker run -d --name bbs-redis -p 6379:6379 redis:7-alpine
# -d 后台运行 | --name 固定名称 | -p 主机端口:容器端口 | 最后是镜像
命令作用状态变化
docker run -d --name bbs-redis -p 6379:6379 redis:7-alpine改变状态从镜像创建并启动一个命名容器。不存在 → 运行中。
docker ps / docker ps -a只读检查分别查看运行中容器和全部容器。退出的容器只在 -a 中出现。
docker stop bbs-redis改变状态请求容器优雅停止。运行中 → 已停止，容器仍存在。
docker start bbs-redis改变状态启动已存在的停止容器。已停止 → 运行中。
docker restart bbs-redis改变状态停止后重新启动。会产生短暂中断，先看日志判断是否必要。
docker rm bbs-redis删除资源删除一个已停止容器。容器消失；命名卷默认不会随之删除。

12 · 日志、进入容器与观察

命令用途BBS 排错用法
docker logs --tail 100 bbs-mysql只读检查查看最后 100 行容器标准输出。先找 MySQL 初始化失败或连接拒绝。
docker logs -f bbs-app只读检查持续跟踪日志，Ctrl+C 退出跟踪。观察 Spring Boot 启动过程。
docker inspect bbs-mysql只读检查查看端口、挂载、网络和状态详情。确认环境变量和 volume 是否挂载。
docker stats --no-stream只读检查获取一次容器资源快照。确认 Elasticsearch 是否因内存不足异常。
docker port bbs-mysql / docker top bbs-mysql只读检查查看端口映射和容器内进程。判断是否映射、主进程是否仍在。
docker exec -it bbs-mysql bash改变状态在运行容器中启动交互 shell。用于临时诊断，不把手工修改当正式配置。
docker cp bbs-app:/app/logs/error.log /tmp/bbs-error.log改变状态从容器复制明确日志文件到主机。确认源和目标方向，冒号左侧是容器。

13 · 数据卷与容器网络

数据卷：让数据库数据离开容器生命周期

docker volume create bbs-mysql-data
docker volume ls
docker volume inspect bbs-mysql-data

docker run -d --name bbs-mysql \
  -v bbs-mysql-data:/var/lib/mysql \
  -e MYSQL_ROOT_PASSWORD=local-only-password \
  mysql:8.4

docker volume rm bbs-mysql-data 带有 删除资源 风险，会删除数据库持久数据。只有确认不再需要且已备份时才执行。

网络：让服务用名字通信

docker network create bbs-network
docker network ls
docker network inspect bbs-network
docker network connect bbs-network bbs-mysql
docker network connect bbs-network bbs-app

# bbs-app 在该网络中可使用 bbs-mysql:3306，不依赖容器 IP

docker network disconnect bbs-network bbs-app 会断开应用网络；docker network rm bbs-network 会删除未被使用的明确网络。

14 · Docker Compose

Compose 用 YAML 记录多个容器、网络、数据卷和启动关系。先逐个理解服务，再使用 Compose。

命令用途风险或判断
docker compose version只读检查确认 Compose 插件可用。旧环境可能只有 docker-compose，先记录版本再决定。
docker compose config只读检查解析并验证 Compose 配置。启动前先运行，检查变量和格式。
docker compose up -d改变状态创建并后台启动当前项目服务。会创建容器、网络，必要时拉镜像。
docker compose ps / docker compose logs -f只读检查查看服务状态和实时日志。先看状态，再按服务看日志。
docker compose restart bbs-app改变状态仅重启指定服务。比重启 Docker 服务影响更小。
docker compose stop改变状态停止服务但保留容器。之后可再次启动。
docker compose down删除资源停止并删除 Compose 容器和默认网络。命名卷默认保留；不要随意追加删除卷选项。

15 · BBS 容器排错顺序

从便宜、只读的检查开始。不要一遇到错误就重装、关防火墙或删数据。

容器存在？→正在运行？→日志健康？→端口已映射？→主机在监听？→防火墙允许？→网络已连接？→卷与权限正确？
容器名称冲突：name is already in use

运行 docker ps -a --filter name=bbs-mysql。决定复用、重命名还是删除明确的旧容器，不要全局清理。

端口占用：port is already allocated

运行 ss -lntp | grep 3306 和 docker ps --format "table {{.Names}}\t{{.Ports}}"，确认占用者后改映射或停止明确服务。

Docker socket permission denied

运行 id、ls -l /var/run/docker.sock 和 systemctl status docker。不要通过给 socket 设置任意人可写来绕过权限。

镜像拉取超时

先检查 curl -I https://registry-1.docker.io、DNS 和虚拟机网络，再单独运行目标 docker pull 保留完整错误。

容器启动后立即退出

运行 docker ps -a、docker logs --tail 100 容器名 和 docker inspect 容器名。退出通常是主进程结束或配置错误。

磁盘空间不足

运行 df -h、docker system df 和 du -sh /var/lib/docker。先识别占用，再删除明确的废弃对象。

16 · 安全清理原则

  1. 先用 docker ps -a、docker images、docker volume ls 看清对象。
  2. 优先删除明确名称：docker rm bbs-practice-web。
  3. 数据库卷与容器分开判断；删容器不等于必须删数据。
  4. prune 会批量删除“未使用”对象，初学阶段不作为默认命令。
  5. 绝不直接删除 /var/lib/docker 来解决空间问题。
