BBS Task 3：用 Linux 虚拟机 Docker 验证 Flyway

目标不是把整个 BBS 部署进 Docker，而是让测试临时启动一个真实 MySQL 8.4，执行 V1 迁移并检查核心表。

1. Maven在 Linux 虚拟机运行测试。
2. Testcontainers调用虚拟机里的 Docker Engine。
3. MySQL 8.4以临时容器启动，随机映射端口。
4. Flyway执行 V1 SQL；测试结束后容器被删除。

Task 3 中 Docker 具体做什么

组件职责项目中的位置
Docker Engine拉取并运行 mysql:8.4Linux 虚拟机
Testcontainers自动创建数据库、用户名和密码，并把 JDBC 地址交给 SpringMySqlContainerSupport
FlywaySpring 启动时执行 V1__baseline_schema.sqlsrc/main/resources/db/migration
JUnit查询数据库元数据，确认 tb_bbs_user 已创建FlywayMigrationTest

测试结束后 MySQL 容器会自动删除。这是测试数据库，不是你日常开发或生产使用的长期数据库。

推荐方案：Maven 和 Docker 都在虚拟机运行

这是最稳定且最安全的方案。Windows 负责写代码；把当前 Git 分支同步到虚拟机，然后在虚拟机运行测试。

步骤 1：确认虚拟机网络地址

ip addr
hostname -I

建议虚拟机使用 NAT 或桥接网络，并确认它能访问互联网以拉取镜像。

步骤 2：确认 Docker Engine 正常

docker version
docker info
docker run --rm hello-world
docker pull mysql:8.4

如果普通用户没有权限：

sudo usermod -aG docker $USER
newgrp docker
docker ps

加入 docker 组等价于授予该用户较高的主机权限，只给可信账号使用。

步骤 3：安装 Java 和 Maven

Ubuntu/Debian 示例：

sudo apt update
sudo apt install -y openjdk-21-jdk maven
java -version
mvn -version

项目以 Java 17 为编译目标，JDK 17 或 21 均可；当前 Windows 验证使用的是 JDK 21。

步骤 4：把 Phase 1 分支放进虚拟机

有 Git 远程仓库时：

# Windows 工作树执行
git push -u origin phase1/baseline-security

# Linux 虚拟机执行
git clone <你的仓库地址> BBS
cd BBS
git checkout phase1/baseline-security

没有远程仓库时：可用 VMware/VirtualBox 共享目录，或在 Windows 创建 Git bundle 后复制到虚拟机：

# Windows PowerShell
git -C D:\JavaWorkSpace\BBS\.worktrees\phase1-baseline-security \
  bundle create D:\bbs-phase1.bundle phase1/baseline-security

# 把 bbs-phase1.bundle 复制到 Linux 后
git clone /path/to/bbs-phase1.bundle BBS
cd BBS
git checkout phase1/baseline-security

步骤 5：运行 Task 3 测试

cd BBS
mvn -Dtest=FlywayMigrationTest,BbsApplicationTests test

另开一个终端可观察临时容器：

watch -n 1 'docker ps --format "table {{.ID}}\t{{.Image}}\t{{.Ports}}\t{{.Names}}"'

步骤 6：判断是否通过

通过标准：
  • 日志显示拉取或启动 mysql:8.4。
  • Flyway 显示迁移到 version 1。
  • FlywayMigrationTest 与 BbsApplicationTests 都通过。
  • Maven 最终输出 BUILD SUCCESS，Failures 和 Errors 都为 0。

常见错误与处理

错误原因处理
Could not find a valid Docker environmentDocker 未启动或当前用户无 socket 权限运行 systemctl status docker、docker ps
Permission denied /var/run/docker.sock用户不在 docker 组使用上面的 usermod，重新登录
Image pull timeout虚拟机网络或镜像站问题先独立执行 docker pull mysql:8.4
Flyway migration failedV1 SQL 与 MySQL 语法或现有表结构冲突保留完整 Flyway 日志，不要手工跳过迁移
Tests run, but table missing迁移位置或 test profile 配置不正确检查 db/migration 和 spring.flyway.enabled=true

高级方案：Windows 直接使用虚拟机 Docker

Testcontainers 可以通过 DOCKER_HOST 使用远程 Docker，但需要 TLS 证书、虚拟机防火墙和远程随机端口连通。这个方案比在虚拟机运行 Maven 更容易出错。

# 仅示意，必须先按 Docker 官方文档配置双向 TLS
$env:DOCKER_HOST = "tcp://<虚拟机IP>:2376"
$env:DOCKER_TLS_VERIFY = "1"
$env:DOCKER_CERT_PATH = "C:\docker-certs"
mvn.cmd "-Dtest=FlywayMigrationTest,BbsApplicationTests" test

不要监听未加密的 tcp://0.0.0.0:2375。Docker API 具有主机级控制能力，局域网中任何能访问该端口的人都可能控制虚拟机。
